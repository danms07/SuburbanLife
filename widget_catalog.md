## 1. Premium Action Header & Split Pane
- **Description**: A double-sized action bar featuring a rich background color (`AppConfig.primaryColor`) with beautifully rounded bottom corners (`Radius.circular(30)`). For wide screens, `LoginScreen` adapts to a premium side-by-side split layout where the left welcome pane features a linear gradient utilizing the `AppConfig.primaryColor` and `AppConfig.gradientEndColor` tokens, displaying the white logo emblem (`AppConfig.whiteLogoEmblemAsset`) with multi-resolution antialiased variants above the application title with 50px spacing (reduced by 40%). In mobile/portrait view, the premium action header displays the white logo emblem (`height: 50`) above the application title with responsive safe area top padding (`MediaQuery.paddingOf(context).top + 24`).
- **Usage**: Used as the top header in `MyHomePage`, `LoginScreen` (on mobile/narrow screens), `SignupScreen`, and `ForgotPasswordScreen` to wow the user and establish visual consistency.
- **Properties**:
  - Top padding: Responsive `MediaQuery.paddingOf(context).top + 24` on mobile login screen (or `+ 16` on standard action headers) to support notch screens while remaining compact on web/desktop.
  - Bottom left/right border radius: 30px
  - Typography: White, bold, clear titles using the app's configured font family.

## 2. Padded Form Cards
- **Description**: Elevated card containers (`elevation: 4`) wrapping input forms to provide a clean, glassmorphism-inspired layering effect on top of the scaffold background.
- **Usage**: Used in authentication and registration screens to house `TextField` and `ElevatedButton` components. In `LoginScreen`, the email input is configured with `TextInputAction.next` and the password input with `TextInputAction.done` alongside `onSubmitted` to trigger the sign-in flow immediately upon pressing Enter on desktop web and hardware keyboards.
- **Properties**:
  - Border radius: 15px
  - Internal padding: 24px

## 3. Cascading Address Selection Dropdowns
- **Description**: Hierarchical dropdown inputs (`DropdownButtonFormField`) providing rapid street-level filtering and sortable numeric selection to locate addresses seamlessly.
- **Usage**: Used in `SignupScreen` during step 2 of resident onboarding and in `AdminUploadPaymentScreen` for uploading payment receipts on behalf of specific addresses.
- **Features**:
  - Dynamic dependency: Number selection automatically filters and sorts based on the selected street name.
  - Rich prefix iconography (`Icons.map` / `Icons.signpost` and `Icons.home`) matching brand colors.

## 4. Security Guard Action Panel
- **Description**: A premium, dedicated dashboard tailored for security guard personnel, integrating a customized brand header (`Expanded` title wrapping + direct logout icon) and an elevated primary call-to-action card (`guard_scan_qr_button`, `elevation: 6`) inside a small-screen overflow-safe scrollable body anchored above a non-interactive bottom `SafeArea` `AppVersionLabel` footer (`guard_app_version_label`).
- **Usage**: Displayed as the primary application surface in `MyHomePage._buildGuardPanel` for users with the `guard` custom claim.
- **Properties**:
  - Header: Deep primary background with responsive wrapping localized guard titles and direct logout access.
  - CTA Card: Large touch target with generous padding (30px), clear iconography, and double-tap route-launch protection (`_isOpeningQrScanner`).
  - Footer: Centered non-interactive localized version caption pinned safely below the action card.

## 5. Multi-Address Inline Header Spinner
- **Description**: An inline header control converting the default title text into a deeply stylized `DropdownButton` allowing residents who own multiple houses to switch active contexts on the fly.
- **Usage**: Displayed inside the *Premium Action Header* when querying multiple approved references.
- **Properties**: Semitransparent white overlays with contrast-heavy menu entries.

## 6. Reviewing Fallback Overlay & Direct Proof Capture
- **Description**: A full-surface lock layout presented to newly onboarded residents featuring a date picker for the property handover/delivery date and direct native camera upload interactions, accompanied by transparent data purging disclosures.
- **Features**: 
  - Displays the specific target property street and number dynamically, and provides an outlined cancellation action to let users abandon the claim if selected incorrectly.
  - Enforces capturing the property delivery date prior to camera photo proof uploads.
  - Uses the modern Flutter `withValues(alpha: ...)` API for theme color transparency overlays to avoid precision loss.

## 7. Dynamic Admin Roll-Up & Item Badges
- **Description**: Reactive notification counters (`Badge`) inside `AdminShellScreen` backed by real-time streams on `ownership_claims`, pending `payments`, and pending `bookings`. When a sidebar/drawer category `ExpansionTile` is collapsed, child counts roll up onto the group header icon (`admin_group_badge_<id>`); when expanded, the group roll-up badge hides and individual counts display next to their specific child items (`Approve Residents`, `Review Bookings`, `Review Pending Payments`). On mobile viewports (`< 900px`), the collapsed `Pending Approvals` Overview card (`mobile_section_pending_approvals`) similarly displays a rolled-up total pending badge (`mobile_badge_pending_approvals`) that hides upon expansion.
- **Usage**: Displayed across the collapsible category groups and `Overview` pending-approval cards in `AdminShellScreen`.

## 8. Adaptive Admin NavDrawer Workspace & Overview
- **Description**: An adaptive administrative shell (`AdminShellScreen`) driven by `LayoutBuilder`. On desktop/wide viewports (`>= 900px`), it renders a persistent `290px` left navigation sidebar alongside the active module content; on mobile/narrow viewports (`< 900px`), it collapses into a modal hamburger `Drawer` with a branded `DrawerHeader`. Organizes all administrative tools into `Overview`, four collapsible `ExpansionTile` groups (`User Management`, `Residential Management`, `Finance`, and `Transparency & Community`), and a direct single-tap `General Settings` leaf tile (`admin_nav_generalSettings`, rendered without an expansion chevron since it is a single item), embedding child screens (`isEmbedded: true`) without duplicate nested `AppBar` headers, and pins a `Logout` tile (`admin_nav_logout`) paired with `AppVersionLabel` (`admin_app_version_label`) to the bottom of the navigation panel. The default `Overview` landing screen renders `Pending Approvals` and `Live Community Status` as static sections on desktop (`>= 900px`) and as expandable/collapsible `ExpansionTile` cards (`mobile_section_pending_approvals` and `mobile_section_community_stats`, collapsed by default) on mobile (`< 900px`), displays the `Visitors currently inside` KPI card (`overview_stat_currently_inside`) exclusively when `config/app_settings.scanOnExitEnabled == true` (in real time alongside `Active Sanctions`), presents a responsive 6-card `Shortcuts` grid (`Create User`, `User Directory`, `Create Announcement` which directly launches the announcement creation modal, `Upload Payment on Behalf`, `Download Financial Reports`, and `Settings`), and includes an Overview-exclusive `Generate Access QR` floating action button (`admin_overview_generate_qr_fab`). Its top `AppBar` is styled with `AppConfig.primaryColor` and white title/foreground icons, conditionally displaying both `Resign Admin Role` (`Icons.waving_hand`) and `Switch to Resident View` (`Icons.person`) only when the signed-in user holds dual `admin` and `resident` roles (`isAdmin && isResident`).
- **Usage**: Serves as the primary administrative workspace rendered by `MyHomePage` when in Admin View.

## 9. Dynamic Facilities Configurator & In-Place Editor
- **Description**: An administrative management interface allowing admins to configure, edit, and delete amenities. Integrates a dynamic `SwitchListTile` to switch between a "Unique Amenity" (locking capacity to 1) and a "Multi-item Amenity" (exposing quantity increment/decrement controls), daily operating hours pickers, advance notice settings, a mutually exclusive **Booking Restriction Policy** selector (`Unrestricted`, `Cooldown Period` measured in `hours | days | months | years` from a booking's end time to the next booking's start time per household, or `Booking Quota` limiting each household to `X` bookings per `daily | monthly | yearly` calendar period) with reactive `ValueListenableBuilder` human-readable rule previews, and a staged **Amenity Documentation** editor (`_buildDocumentsEditorSection`) allowing admins to attach templates/forms/rules (`pdf`, `doc`, `docx`, `xls`, `xlsx`, `jpg`, `jpeg`, `png`, `webp` up to 10 MB) with per-document requirement modes (`mandatory_return`, `optional_return`, `informative`). Staged edits inside `_EditFacilityDialog` never mutate live Storage files if dismissed via Cancel, while Save uploads new files (`Content-Disposition: attachment`) and deletes removed Storage objects cleanly.
- **Usage**: Used inside `AdminFacilitiesScreen`.

## 10. Keyed Booking Summary Card & Dedicated Booking Detail Screen
- **Description**: A two-stage Master-Detail administrative booking review flow aligned with Resident and Payment approvals to prevent accidental inline approve/reject taps and visual clutter. In `AdminBookingApprovalScreen`, each pending `bookings` entry renders as a compact, button-free, stateful `_BookingSummaryCard` (`key: ValueKey(bookingId)` to cache facility/user/address lookups) displaying the facility name, wrapping `Pending Review` badge, localized time slot pill, applicant name, resolved household address (`streetName #number`), attachment count pill (`booking_attachments` badge when applicable), and trailing chevron (`Icons.chevron_right`). Tapping a card (`booking_card_<bookingId>`) navigates to `AdminBookingDetailScreen`, which adapts via `LayoutBuilder`: when submitted attachments or facility returnable templates exist on wide viewports (`> 650px`), it places the real-time **Submitted Documentation** pane (`booking_attachments/{bookingId}` with requirement mode badges, responsive **View / Download** `approval_view_attachment_<bookingId>_<docId>` controls, and inline `RotatableImagePreview` containers for `jpg`, `jpeg`, `png`, `webp` attachments) in the left `flex: 3` pane and full schedule/applicant/address details with `Reject` / `Approve Booking` actions on the right (`flex: 2`); when no documentation panel applies on wide viewports, it centers a bounded single-card layout, and on mobile viewports (`<= 650px`) it stacks booking info cleanly above documentation and action buttons before popping back upon approval (`approvalMessage`) or rejection (`rejectionReason`).
- **Usage**: Exposed via `AdminBookingApprovalScreen` and `AdminBookingDetailScreen`.

## 11. Multi-Report Financial Bundle & Matrix Exporter
- **Description**: A mobile-responsive financial reporting interface (`AdminPaymentReportScreen` / **Financial Reports**) placing the live financial KPI summary preview card (`financial_summary_preview_card` with overflow-safe wrapped title and Brought-Forward Balance, Maintenance Quota Income, Sanction Income, Active Expenses, and Ending Accumulated Budget) at the top, followed by `Start Month` / `End Month` dropdown selectors (`isExpanded: true`, stacked below `520px`), and all privacy-aware download/action controls grouped at the bottom (stacking secondary buttons cleanly on `< 520px`). Supports exporting a one-click **Multi-Report Financial Bundle** (`download_report_bundle_button` with `Icons.download`, saving both the private Address Payment Status Matrix CSV and the Financial Ledger & Accumulated Budget Summary CSV), downloading each CSV independently (`download_status_matrix_only_button`, `download_financial_ledger_only_button`) with spreadsheet formula neutralization (`CWE-1236`), publishing an **aggregated, PII-free bilingual (`en` & `es`) Markdown Financial Summary** (`publish_transparency_report_button` / `_PublishTransparencyDialog`) under a single deterministic period `docId` (`financial_summary_<start>_to_<end>` / `financial_summary_<start>`) with period-only title (`YYYY-MM – YYYY-MM` / `YYYY-MM`) and localized category headings into the localized **Financial Reports** Transparency folder without disclosing address matrices, and navigating to `AdminBulkPaymentImportScreen` (`open_bulk_payment_import_button`).
- **Usage**: Exposed via `AdminPaymentReportScreen` (`AdminShellScreen` Finance section and Overview shortcuts).

## 12. Keyed Resident Summary Card & Dedicated Resident Approval Detail Screen
- **Description**: A two-stage Master-Detail administrative ownership-claim review flow matching the Payment Approval experience to prevent accidental inline approve/reject misclicks on mobile devices. In `AdminResidentApprovalScreen`, each pending `ownership_claims` entry renders as a compact, button-free, stateful `_ResidentSummaryCard` (keyed via `ValueKey(doc['id'])` to cache address and applicant lookups) displaying the physical address (`streetName #number`), `Pending Review` badge, applicant name chip, property handover date chip, and trailing chevron. Tapping a card pushes `AdminResidentDetailScreen`, which adapts via `LayoutBuilder`: on wide screens (`> 650px`), it displays the expanded `RotatableImagePreview` ownership-proof viewer (`ownership_proof_thumbnail`) on the left and the claim metadata (address header, applicant name, PII-masked email chip, handover date, submission date, privacy-by-design Storage deletion notice) with `Reject` / `Approve Resident` (`AppConfig.primaryColor`) action buttons on the right; on mobile screens (`<= 650px`), it renders a responsive vertical `Column` with constrained scrollable metadata and an `Expanded` proof preview. Administrators can rotate sideways deeds/utility bills in 90-degree increments directly inline (`inline_rotate_image_button` / `inline_proof_rotated_box`) or open the full-screen interactive zoom viewer (`fullscreen_proof_button` / `showInteractiveImageDialog` with 20% screen padding, pinch-to-zoom, pan, and `rotate_image_button`, preserving `initialQuarterTurns`).
- **Usage**: Exposed via `AdminResidentApprovalScreen` and `AdminResidentDetailScreen`.

## 13. Keyed Payment Summary Card & Dedicated Payment Detail Screen
- **Description**: A two-stage address-level administrative payment review flow designed to prevent accidental approval misclicks on mobile devices. In `AdminPaymentApprovalScreen`, each pending submission renders as a compact, stateful `_PaymentSummaryCard` (keyed via `ValueKey(doc['id'])` to cache address lookups) showing basic payment info (physical address `streetName #number`, `$amount` badge, concept chip, explicitly labeled `Date of payment` chip, and trailing chevron) without inline action buttons. Tapping a card navigates to `AdminPaymentDetailScreen`, which adapts via `LayoutBuilder`: on wide screens (`> 650px`), it places the expanded `RotatableImagePreview` proof-of-payment viewer (`payment_receipt_thumbnail`, `payment_inline_rotate_button`, `payment_fullscreen_button`) on the left and the payment details (`Folio`, `Date of payment`, `Period paid`, and for sanction payments the linked sanction's requested fine amount, infraction description, and an inline `RotatableImagePreview` infraction photo viewer) with the `Reject` / `Approve Payment` (`AppConfig.primaryColor`) action buttons on the right; on narrow/mobile screens (`<= 650px`), it uses a constrained scrollable metadata section above an `Expanded` receipt preview. Both receipt and sanction evidence previews expose top-right circular buttons for inline 90-degree rotation and launching `showInteractiveImageDialog` with `initialQuarterTurns` preserved.
- **Usage**: Exposed via `AdminPaymentApprovalScreen` and `AdminPaymentDetailScreen`.

## 14. Categorized Multi-Period & Advance Payment Selector
- **Description**: An interactive payment submission interface (`PaymentScreen` & `AdminUploadPaymentScreen`) that renders an amount input field and categorizes candidate billing periods into **Due / Pending Months** (missing/rejected periods from delivery date up to current month) and **Advance / Upcoming Months** (up to 12 months ahead). Enables multi-selection of periods via `FilterChip` items with visual status icons (paid checkmark, reviewing hourglass) and automatic chronological sorting. Uploading a proof of payment transitions the address status to `pending`. When the status is `pending` within the active grace period (`isWithinGracePeriod == true`), the resident is considered `paid` and retains unrestricted access to bookings and QR passes.
- **Usage**: Used inside `PaymentScreen` and `AdminUploadPaymentScreen` to support single and advance multi-month payments.

If the collection is empty, the "Book Facility" shortcut item on the dashboard grid and the "Manage Bookings" menu item in the navigation drawer are dynamically removed to avoid clutter and layout alignment gaps.
- **Usage**: Main screen feature navigation dashboard and navigation drawer widgets.

## 17. Custom Branded QR Access Card
- **Description**: An on-the-fly generated shareable/downloadable graphic card (`800x1200` PNG). Uses a Custom Paint canvas recorder layout combining a branded header strip (featuring the brand app logo and name), a centered QR access code, a content divider, and five custom rows detailing the guest's name, authorized address, access category, validity/expiry status, and vehicle information. Leverages `share_plus` with `ShareParams`, `XFile.fromData`, and `fileNameOverrides` for cross-platform native device sharing, with an automatic web download fallback when native sharing is unavailable on desktop browsers.
- **Usage**: Dynamically compiled when the user clicks 'Share Code' or 'Download Code' in `QrGeneratorScreen`.

## 18. Roommate QR Code Onboarding & Scanner
- **Description**: A dual-sided QR and UID account linking system for roommates and family members. On the unlinked account onboarding card (`main.dart`), an interactive `SegmentedButton` lets users toggle between "Claim Property" and "Join as Roommate", with a persistent **Sign Out** (`onboarding_logout_button`) action beneath both tabs calling `Backend.auth.signOut()`. The Roommate tab presents a high-contrast `QrImageView` encoding `roommate_uid:$uid`, user credentials, a selectable plain-text UID box with an inline "Copy to Clipboard" icon button (`Clipboard.setData`), a full-width copy action button, and a live stream builder waiting indicator. In `RoommatesScreen`, primary residents can launch an inline camera QR scanner sheet powered by `MobileScanner` with camera selector controls (back/front camera toggle in sheet header and floating button on scanner preview, defaulting explicitly to rear camera) to scan roommate QR codes or manually type/paste a roommate UID or email address using the built-in `content_paste` suffix button in the input field.
- **Usage**: Used during initial onboarding in `main.dart` and inside `RoommatesScreen`.

## 20. Bulk Address Import CSV Manager

Offers responsive `Wrap` **Download CSV Template** (`address_import_template.csv` via `CsvDownloadHelper`) and **Copy CSV Template** helpers, live row preview listing, and collision checks against existing database records.

## 21. Admin Settings & SMTP Configurator
- **Description**: A collapsible, card-based configuration panel (`AdminSettingsScreen`) organized into 5 expandable/collapsible `ExpansionTile` cards (`settings_card_payment`, `settings_card_access_control`, `settings_card_rejection_reasons`, `settings_card_smtp`, and `settings_card_email_template`, collapsed by default for fast navigation) with a live auto-save status banner (`settings_autosave_banner` / `settings_autosave_status`). Automatically persists all switches (`Scan on exit`, `Enable Automatic Welcome Emails`, and `Use SSL/TLS`) and general settings (payment cutoff day slider `onChangeEnd`, grace period slider `onChangeEnd`, schedule timezone dropdown, optional Opening Balance `initialBudgetBalance` + effective `initialBalancePeriod` month selector inside `settings_card_payment`, and custom payment rejection reason additions/deletions) in real time without overwriting unsaved text edits. Manual saving is required exclusively for the **SMTP Server Configuration** text fields (`save_smtp_config_button`, alongside standard port preset chips `587`, `465`, `25`, password visibility toggle, and an interactive `Test Connection` handshake tool) and the **Custom Welcome Message** template (`save_email_template_button`, featuring `%password%`, `%name%`, `%email%`, `%address%`, `%role%`, `%appName%` placeholder chips, automatic pre-fill of the localized default template body when no custom body is saved, and a responsive compact `reset_default_template_button` stacked cleanly beneath the description on mobile viewports `< 520px`).
- **Usage**: Exposed via `AdminSettingsScreen`.

## 24. Release Error Fallback Screen
- **Description**: A user-friendly, beautifully styled fallback error screen displayed during fatal framework rendering or widget build crashes in release builds (intercepted via `ErrorWidget.builder`). Prevents standard red/grey crash screens by presenting a clean alert card with bilingual support (`AppLocalizations`) explaining that an automatic incident report has been dispatched to Firebase Crashlytics.
- **Usage**: Configured globally in `main.dart` via `ErrorWidget.builder` and defined in `lib/core/widgets/error_fallback_screen.dart`.

## 25. User Directory Summary Card & Dedicated Account Detail Screen
